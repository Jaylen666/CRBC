# Additional RTL bugs

Source locations refer to the upstream revisions checked during evaluation. OpenPiton `1c6bfd2` pins Ariane `4c01614` and RISC-V Debug `e19d69e`. OpenTitan was checked at `3a7f6947`.

To reduce the risk of misuse, we omit the exact line numbers and reproduction details for the two DMA security findings. We reproduced both failures in module-level tests on the evaluation design and confirmed that each disappeared after a targeted correction in the test copy.

| SoC | IP | Upstream RTL location | Defect | Trigger condition | Effect | Type |
| --- | --- | --- | --- | --- | --- | --- |
| OpenPiton | CLINT | Ariane `corev_apu/clint/clint.sv:99, 103, 138, 145` | **CLINT endpoint address aliasing.** The read and write decoders include one address beyond the implemented `MSIP` and `MTIMECMP` register ranges. The derived selector can wrap to an implemented hart index. | A privileged access targets the first unimplemented slot after either register range. Aliasing depends on the hart configuration. | An out-of-range access can read or modify the software-interrupt or timer-compare state of an implemented hart. | Functional |
| OpenPiton | Ariane CSR register file | Ariane `core/csr_regfile.sv:519, 845` | **Reserved MPP value accepted.** The full-register write to `mstatus` leaves `MPP` unchecked. The return logic subsequently uses the stored field as the next privilege mode. | Machine-mode firmware leaves a reserved encoding in `MPP` before returning from a trap. | Execution enters a reserved privilege state with inconsistent architectural behaviour. | Functional |
| OpenPiton | Ariane CSR register file | Ariane `core/csr_regfile.sv:661` | **Delayed dirty-state summary update.** `mstatus.SD` is computed from the previous `FS` and `XS` values, so it can lag the underlying dirty state by one cycle. | Floating-point state becomes dirty while the previous dirty-state summary is clear. | A status read in that cycle can report `SD` as clear even though `FS` already reports dirty state. | Functional |
| OpenPiton | RISC-V Debug Module | RISC-V Debug `src/dm_csrs.sv:538–545` | **Invalid debug hart selection aliases a valid hart.** The module truncates the selected hart ID before checking its range. The check can therefore accept the truncated ID of a nonexistent hart. | In a single-hart configuration, a debugger requests a nonexistent hart whose ID aliases the implemented hart after truncation. | A debug halt or resume request can reach a hart other than the one selected by the debugger. | Functional |
| OpenPiton | Ariane CSR register file | Ariane `core/csr_regfile.sv:339, 345, 573, 1174` | **Dropped `minstret` writes.** The CSR write updates a temporary value after the logic has already assigned the counter's next state. The updated temporary value is never latched. | Machine-mode software writes the retired-instruction counter. | The counter silently continues from its prior value, which invalidates software attempts to initialise or adjust instruction counts. | Functional |
| OpenTitan | DMA | `hw/ip/dma/rtl/dma.sv` | **Stale DMA address range check.** The address used for range validation can differ from the address used for the transfer. | Certain DMA transfer configurations. | A transfer can reach memory outside the configured range or use an unintended address. | Security and functional |
| OpenTitan | DMA | `hw/ip/dma/rtl/dma.sv` | **Ineffective DMA digest clearing.** The digest-clearing request may leave the digest registers unchanged. | Software requests that the DMA clear a completed digest. | Digest data can remain readable after software expects it to have been cleared. | Security and functional |
| OpenTitan | KMAC | `hw/ip/kmac/rtl/kmac.sv:777–779` | **Missing message FIFO error reporting.** The shared error event omits the message FIFO fault. That event controls whether the error code is written, even though the error-code decoder has a FIFO case. | A message FIFO integrity fault occurs without another source asserting the shared error event. | Software can miss or misidentify the FIFO error in `ERR_CODE`. The separate fatal alert still fires. | Functional |
| OpenTitan | UART | `hw/ip/uart/rtl/uart_core.sv:387` | **Spurious UART timeout on an empty FIFO.** The timeout event compares the counter against the programmed threshold without checking FIFO occupancy. An empty receive FIFO holds the counter at zero. | Receive timeout is enabled with a zero threshold while the receive FIFO is empty. | The receive-timeout event stays asserted and can repeatedly raise an interrupt after software clears it. | Functional |
